# AmneziaWG GUI (portable)

Портативное Windows-приложение для управления сервером
[bivlked/amneziawg-installer](https://github.com/bivlked/amneziawg-installer)
по SSH. Все действия выполняются на сервере через `manage_amneziawg.sh`;
на самом сервере ничего устанавливать и открывать не нужно.

> **Совместимость:** приложение подходит только для серверов, установленных
> проектом [bivlked/amneziawg-installer](https://github.com/bivlked/amneziawg-installer).
> Это сторонний клиент: автор установщика не поддерживает GUI и не отвечает
> за его работу.

## Возможности

- Профили серверов: IP/хост, SSH-порт, пользователь, ключ или пароль,
  путь к `manage_amneziawg.sh` и каталогу AWG.
- Обзор состояния: сервис, интерфейс, порт, модуль ядра, UFW, клиенты,
  трафик и последние handshake.
- Клиенты: список, поиск, добавление (срок, `--psk`, индивидуальные
  `AllowedIPs`), изменение `DNS` / `Endpoint` / `AllowedIPs` /
  `PersistentKeepalive`, `regen`, удаление.
- QR-коды `.conf` и `vpn://`, просмотр и скачивание `.conf`, `.png`,
  `.vpnuri`, `.vpnuri.png`. Если PNG на сервере отсутствует, QR строится
  локально из конфига.
- Сервер: `check --json`, `awg show`, `awg0.conf` и `awgsetup_cfg.init`
  с маскированием секретов, системный снимок, журналы, резервные копии,
  восстановление.
- Диагностика: `check`, `show`, `diagnose` (в том числе сравнение с
  профилями операторов).
- Команды: `add`, `remove`, `list`, `stats`, `regen`, `modify`, `check`,
  `show`, `diagnose`, `backup`, `restore`, `restart`, `repair-module`,
  `help` — в графическом виде, с подтверждением опасных операций.
- SSH-консоль с историей и переключателем `sudo`.
- Журнал действий приложения (без приватных ключей и паролей).
- Обслуживание: очистка `manage_amneziawg.log`, скачивание резервной копии на ПК
  и загрузка архива `.tar.gz` на сервер по SFTP.
- Вкладка «О программе»: совместимость, ссылки на проект `bivlked`, обратная связь,
  проверка обновлений на GitHub Releases и благодарность автору.

## Требования

- Windows 10/11 x64.
- Сервер с установленным `amneziawg-installer` (проверено на `manage`
  v6.x) и доступом по SSH.
- SSH-ключ в формате OpenSSH/PEM либо пароль SSH.
  Формат PuTTY `.ppk` не поддерживается — конвертируйте его в PuTTYgen
  (`Conversions → Export OpenSSH key`).
- Пользователь `root` или пользователь с рабочим `sudo`.

## Быстрый старт

1. Запустите `AmneziaWG-GUI-1.1.0-portable.exe`.
2. Нажмите `+` рядом с «Профили» и заполните:
   - название (произвольно);
   - IP/хост, например `203.0.113.10`;
   - SSH-порт, например `22` или ваш нестандартный порт;
   - пользователя, обычно `root`;
   - файл приватного ключа или вставьте ключ в поле ниже.
3. Нажмите «Сохранить и подключиться».
4. При первом подключении приложение сохраняет отпечаток SSH-ключа
   сервера (TOFU) и показывает его в обзоре. Если отпечаток позже
   изменится, подключение будет заблокировано до явного подтверждения.
5. Если пользователь не `root`, приложение запросит пароль `sudo`.
   Пароль хранится только в памяти до отключения.

## Безопасность

- Профили (включая приватные ключи и пароли) шифруются через Windows
  DPAPI (`safeStorage`) и привязаны к учётной записи Windows.
- Пароль `sudo` не сохраняется на диск и живёт только в памяти процесса
  до отключения или выхода.
- SSH host key проверяется по схеме TOFU. При смене отпечатка подключение
  блокируется и показывает старый и новый отпечатки.
- Приватные ключи серверных конфигов и клиентских `.conf` по умолчанию
  маскируются; показ требует отдельного подтверждения.
- Все пользовательские аргументы валидируются и экранируются для shell.
  Имена клиентов: `^[A-Za-z0-9_-]{1,64}$`.
- Опасные операции (`remove`, `restore`, `restart`, `repair-module`)
  требуют ввода подтверждающего слова.
- Приложение не содержит телеметрии и не обращается в сеть, кроме
  выбранного SSH-сервера.

## Сборка

```powershell
cd awg-gui
npm install
npm run dist
```

Результат: `dist\AmneziaWG-GUI-1.1.0-portable.exe`.

Сборка не требует Python: нативный модуль `cpu-features` (опциональная
зависимость `ssh2`) не пересобирается (`npmRebuild: false`), а `ssh2`
использует pure-JS fallback. Это важно для машин без Visual Studio
Build Tools.

Для запуска из исходников:

```powershell
npm start
```

## Где хранятся данные

- Portable-сборка: каталог `awg-gui-data` рядом с `.exe`.
- Если папка с `.exe` недоступна для записи (например, `Program Files`),
  приложение автоматически использует
  `%APPDATA%\amneziawg-gui\awg-gui-data`.
- Запуск из исходников: `awg-gui\awg-gui-data`.

В каталоге:

- `profiles.json` — зашифрованные профили;
- `known_hosts.json` — доверенные отпечатки SSH;
- `awg-gui.log` — журнал приложения.

Удаление каталога сбрасывает профили и доверенные ключи.

## Ограничения

- Приложение не работает с сервером без `manage_amneziawg.sh`
  (поддерживается контракт v6.x).
- Нет доступа к серверу по Telnet/Web; только SSH.
- Не поддерживаются `.ppk`, аппаратные ключи и SSH-агент.
- `restore` и `repair-module` могут занимать минуты; окно вывода
  показывает прогресс и не закрывается до завершения.
- Пароль `sudo` может быть запрошен повторно после перезапуска
  приложения или переподключения.
- На сервере ничего не устанавливается: GUI — только SSH-клиент.

## Диагностика проблем

| Симптом | Что проверить |
|---|---|
| `SSH-ключ сервера изменился` | Смена ОС/переустановка сервера или MITM. Сверьте отпечаток с сервером, затем «Доверять новому ключу». |
| `Не удалось прочитать SSH-ключ` | Путь к ключу, права доступа, формат OpenSSH/PEM. |
| `sudo отклонил пароль` | Пароль пользователя, членство в `sudo`, `sudo -n true` на сервере. |
| `На сервере не найден ...manage_amneziawg.sh` | Укажите правильный путь в профиле. |
| Пустой список клиентов | Проверьте `check` и права; `list -v --json` должен возвращать JSON. |
| `check не вернул JSON` | Версия `manage` не поддерживает `--json` или скрипт пишет в stderr. |
| QR не создаётся | На сервере нет `.png`; включите локальную генерацию (по умолчанию) или выполните `regen`. |

## Разработка и тесты

- `main.js` — Electron main, IPC, SSH-сессии, файлы, настройки сервера.
- `preload.js` — минимальный `contextBridge` API.
- `lib/ssh-manager.js` — SSH2, sudo, потоковый вывод, чтение файлов.
- `lib/actions.js` — сборка и валидация команд `manage`.
- `lib/store.js` — профили, DPAPI, known_hosts, настройки.
- `lib/util.js` — экранирование, JSON, валидаторы.
- `renderer/` — интерфейс без Node.js-доступа.

Для локальной проверки без реального сервера можно поднять mock SSH
(см. `mock-ssh-server.js` в тестовом каталоге) и подключиться к
`127.0.0.1:2222`.

## Обслуживание

Вкладка «Обслуживание» содержит три операции:

- **Очистить лог управления** — обнуляет `manage_amneziawg.log` в каталоге AWG.
  Сервер, клиенты, ключи и конфигурация не затрагиваются; действие требует
  подтверждения.
- **Скачать бэкап на ПК** — сохраняет выбранный архив
  `awg_backup_*.tar.gz` в выбранное место через SFTP. На сервере ничего
  не меняется.
- **Загрузить бэкап на сервер** — отправляет локальный архив `.tar.gz`
  в каталог `backups` по SFTP. Существующие файлы не перезаписываются,
  проверяется расширение и gzip-сигнатура, лимит — 256 МБ.

## Подпись и SmartScreen

Сборка не подписана: для подписи нужен коммерческий сертификат
code signing (OV/EV). Без него Windows SmartScreen может показывать
предупреждение «Неизвестный издатель» — это ожидаемо для неподписанных
portable-сборок, репутация набирается со временем и загрузками.

Если сертификат появится, подпись включается без правок кода:

```powershell
$env:CSC_LINK = "C:\path\to\certificate.pfx"
$env:CSC_KEY_PASSWORD = "пароль"
npm run dist
```

Самоподписанный сертификат SmartScreen не устраняет — он подходит только
для внутреннего тестирования.
